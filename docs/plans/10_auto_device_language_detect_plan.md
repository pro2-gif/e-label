# 기기 기본 언어 자동 감지 및 맞춤형 언어 뷰어 초기화 구현 계획서

## 1. 개요
* **목적**: 스마트폰이나 PC에서 QR 코드를 스캔하거나 제품 정보를 열었을 때, 기기(브라우저)에 설정된 기본 언어를 자동으로 감지하여 해당 국가의 언어(`KO`, `EN`, `JP`, `ZH-CN`, `ZH-TW`)로 즉시 첫 화면을 표시.
* **배경**: 한국 사용자는 한국어가 바로 보이고, 해외 바이어(미국, 일본, 중국, 대만, 홍콩, 유럽 등)는 자기 나라 언어로 제품 정보가 가장 먼저 보이도록 하여 전시회 및 글로벌 수출 대응력 극대화.

---

## 2. 세부 구현 내용

### 1) 기기 언어 감지 로직 (`getDevicePreferredLanguage`)
* 브라우저 표준 API인 `navigator.languages` 및 `navigator.language`를 분석하여 5대 언어 중 최적 매칭:
  1. **한국어**: `ko`, `ko-KR` ➔ `ko` (국문)
  2. **일본어**: `ja`, `ja-JP` ➔ `jp` (일본어)
  3. **중국어 번체**: `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant` ➔ `tw` (중국어 번체)
  4. **중국어 간체**: `zh-CN`, `zh-SG`, `zh-Hans` 등 ➔ `ch` (중국어 간체)
  5. **영어**: `en`, `en-US`, `en-GB` 등 ➔ `en` (영문)
  6. **기타 언어 (프랑스어, 독일어, 스페인어, 베트남어 등)**: 해외 바이어 대응을 위해 글로벌 공용어인 `en` (영문)으로 자동 폴백 처리.

### 2) 우선순위 정책 (Priority Rule)
* **1순위 (URL 지정 우선)**: QR 코드나 링크 자체에 언어 파라미터(`&l=e`, `&l=j`, `&l=c`, `&l=t`, `&l=k` 또는 `&lang=...`)가 명시되어 있는 경우 해당 언어를 최우선 적용.
* **2순위 (기기 언어 자동 감지)**: 언어 파라미터가 없는 통합 QR 코드 또는 기본 링크로 진입한 경우, 기기 언어 감지 함수 결과 적용.
* **상단 버튼 연동**: 자동 감지된 언어에 맞춰 상단 언어 선택 버튼(`KO`, `EN`, `JP`, `ZH-CN`, `ZH-TW`)의 활성 상태(`active`)도 자동으로 동기화. 사용자가 상단 버튼을 클릭하면 언제든 원하는 언어로 즉시 전환 가능.

### 3) 수정 대상 파일
* `index.html`:
  * `getDevicePreferredLanguage()` 함수 추가.
  * `initViewer()` 초기 언어 결정 로직 개선.
  * QR 메이커 모드(`initQrMaker`)에서도 번체(`tw`) 파라미터(`&l=t`) 생성 안전망 추가.

## 3. 검증 및 배포 절차
1. 로컬 환경에서 기기 언어별 감지 시뮬레이션 테스트:
   - 한국어 브라우저 ➔ KO 자동 선택
   - 일본어 브라우저 ➔ JP 자동 선택
   - 대만/홍콩 브라우저 ➔ ZH-TW 자동 선택
   - 중국 브라우저 ➔ ZH-CN 자동 선택
   - 영어/기타 외국어 브라우저 ➔ EN 자동 선택
2. 수인의 사전 검토 및 승인 후 코드 반영 및 Git 커밋.
3. 수인의 요청에 따라 깃허브 클라우드 백업(Push) 및 Vercel 실서버 반영.
